ВНЕСИ СЛЕДУЮЩИЕ ИЗМЕНЕНИЯ В ПРОЕКТ PET CONNECT.

ВАЖНО: это дополнение к существующему техническому заданию. Сохрани всю ранее описанную функциональность: двух AI-агентов, PostgreSQL, Python backend, React frontend, TypeScript, парсер животных, анкеты, менеджерскую панель и Pet Tinder.

# 1. ИЗМЕНИТЬ ЛОГИКУ РЕГИСТРАЦИИ И ДОСТУПА К ИИ

Главное требование: пользователь должен получать возможность пользоваться AI-ботом сразу после успешной регистрации.

Пользовательский сценарий:

1. Пользователь открывает сайт PET CONNECT.
2. Нажимает кнопку регистрации.
3. Заполняет необходимые поля: имя, email и пароль.
4. Backend проверяет данные.
5. Создаёт аккаунт пользователя в PostgreSQL.
6. Автоматически авторизует пользователя.
7. Создаёт пользовательскую сессию.
8. Перенаправляет пользователя непосредственно в чат с AI-ассистентом.

После регистрации пользователь СРАЗУ может общаться с ИИ.

Запрещено требовать:
- Ручного подтверждения аккаунта менеджером.
- Одобрения анкеты.
- Предварительного заполнения полной анкеты.
- Дополнительной регистрации в другом разделе.
- Ожидания активации аккаунта.

Неавторизованные пользователи могут просматривать публичную главную страницу, но не могут использовать чат, сохранять предпочтения и получать персональные рекомендации.

После регистрации:
- Пользователь автоматически получает роль USER.
- Создаётся пустая персональная анкета.
- Создаётся первая беседа с рассказчиком.
- Пользователь сразу попадает в чат.

Менеджерские аккаунты должны создаваться отдельно администратором. Нельзя позволять обычному пользователю самостоятельно назначать себе роль MANAGER.

# 2. ИЗМЕНИТЬ ПЕРВЫЙ ЗАПУСК ЧАТА

Не показывать пользователю длинную анкету сразу после регистрации.

Вместо этого рассказчик должен самостоятельно начать дружелюбный разговор.

Пример:

«Привет! Очень рад помочь тебе найти нового друга. Давай немного познакомимся! Для начала расскажи, кого ты хотел бы приютить — собаку, кошку или, может быть, кого-то другого?»

Пользователь отвечает обычным сообщением.

Рассказчик постепенно задаёт вопросы, извлекает предпочтения и автоматически сохраняет ответы в PostgreSQL.

Если пользователь не хочет отвечать на определённый вопрос, он может пропустить его.

Если пользователь вводит неправильный ответ, он может исправить его непосредственно в чате или через страницу «Моя анкета».

Пользователь должен иметь возможность пользоваться ИИ даже при незаполненной анкете.

Рекомендации становятся точнее по мере заполнения предпочтений.

Каждая карточка содержит:
- Фотографию.
- Имя животного.
- Возраст.
- Вид и породу.
- Краткое описание.
- Характер.
- Приют.

Не перегружать карточки информацией.

Использовать качественные фотографии с правильным кадрированием.

На главной странице показывать несколько актуальных животных.

# 6. ИНТЕРФЕЙС ЧАТА

Чат должен быть частью общей дизайн-системы PET CONNECT.

Не использовать визуально стандартный интерфейс ChatGPT.

Сделать собственную композицию:
- Боковая панель с историей диалогов.
- Основная область переписки.
- Приятная приветственная заставка.
- Большое поле ввода.
- Карточки питомцев прямо внутри диалога.
- Кнопки быстрых ответов.
- Анимации появления сообщений.

При первом открытии чата показывать приветствие рассказчика.

После того как пользователь закончит отвечать на вопросы, рассказчик должен предложить перейти к просмотру питомцев.

Карточки животных должны быть интерактивными React-компонентами.

# 7. СТРАНИЦА МОЕЙ АНКЕТЫ

Создать отдельную страницу, где пользователь может:
- Просматривать сохранённые предпочтения.
- Изменять ответы.
- Добавлять пожелания.
- Удалять необязательные ответы.
- Просматривать историю изменений.

Все изменения сразу сохранять в PostgreSQL.

После изменения анкеты обновлять контекст рассказчика.

# 8. МЕНЕДЖЕРСКАЯ ПАНЕЛЬ

Сохранить отдельную панель MANAGER.

Менеджер должен видеть:
- Зарегистрированных пользователей.
- Их анкеты.
- Предпочтения.
- Историю общения.
- Избранных животных.
- Текущий этап подбора.

Доступ исключительно по роли MANAGER.

# 9. AI CONTROL ROOM

Сохранить отдельный демонстрационный режим взаимодействия рассказчика и эксперта.

Визуально показать:
- NARRATOR.
- EXPERT.
- DATABASE.
- USER.

Показывать реальные события backend через WebSocket.

Дизайн панели должен соответствовать общей визуальной идентичности PET CONNECT, но оставаться функциональным и информативным.

# 10. ОБЩИЕ ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

Сохранить существующий стек:

Backend:
Python + FastAPI.

Frontend:
React + TypeScript + Vite.

PostgreSQL.

SQLAlchemy.

Alembic.

AI:
Два независимых агента NARRATOR и EXPERT.
