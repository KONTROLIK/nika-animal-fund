# Алгоритм подбора карточек PET CONNECT

## Пользовательский сценарий

Карточки питомцев не показываются как персональные рекомендации до завершения интервью.

```text
Регистрация
  → глубокое интервью
  → сохранение портрета владельца
  → завершение всех тем
  → разблокировка «Выбор сердцем»
  → Tinder-свайпы
```

До завершения интервью:

- ответ помощника содержит следующий вопрос;
- `recommendations` в ответе чата пустой;
- `/api/tinder/next` возвращает `409`;
- `/api/tinder/{animal_id}` не принимает свайп.

После завершения интервью:

- backend рассчитывает порядок карточек;
- пользователь видит карточки в формате Tinder;
- `like` добавляет питомца в избранное;
- `skip` сохраняет пропуск;
- уже просмотренные карточки не возвращаются.

## Что происходит после последнего ответа

1. Последний ответ проходит через экспертный AI-агент. Агент извлекает только явно подтверждённые предпочтения и факты; он не придумывает свойства питомцев.
2. Backend проверяет, что закрыты все 15 тем интервью. Только после этого становится доступен `/api/tinder/next` и открывается экран «Выбор сердцем».
3. Для каждого доступного питомца backend сравнивает ответы владельца с данными каталога, начисляет баллы по правилам ниже и сортирует карточки по убыванию результата.
4. Первый результат показывается не списком, а одной верхней карточкой Tinder. Свайп вправо (`like`) сохраняет питомца в избранное, свайп влево (`skip`) сохраняет пропуск; следующая карточка появляется только после сохранения решения.

Если AI-режим отключён или внешний AI временно недоступен, применяется тот же локальный анализ и тот же детерминированный ranking. Поэтому AI помогает понять ответ человека, но не может открыть подбор раньше времени или подменить факты из каталога.

## Источники данных

Подбор использует только записи из PostgreSQL, импортированные из публичного каталога фонда:

- вид животного;
- возраст;
- приют;
- описание;
- характер;
- ограничения и совместимость;
- здоровье, если оно опубликовано фондом;
- статус доступности.

AI не имеет права создавать новые сведения о животных. Если поле отсутствует в каталоге, оно не участвует в оценке.

## Сигналы владельца

Алгоритм использует два уровня данных:

1. **Видимые предпочтения** — вид питомца, ритм жизни, тип дома и пожелания.
2. **Приватный портрет** — факты и ответы глубокого интервью, которые сохраняются в `owner_portraits` и не выводятся целиком в обычной анкете.

В приватном портрете учитываются, когда они явно подтверждены пользователем:

- наличие детей;
- наличие других животных;
- спокойный или активный образ жизни;
- бытовые ограничения;
- опыт ухода;
- особенности дома;
- требования к характеру и уровню активности.

## Текущая оценка

Для каждой доступной карточки считается детерминированный score:

- `+12` — вид питомца совпадает с предпочтением;
- `+5` — опубликованная информация о питомце подходит для квартиры;
- `+4` — опубликованная информация совпадает с активным ритмом;
- `+3` — подтверждена совместимость с детьми;
- `-2` — опубликовано ограничение для семьи с детьми;
- `+3` — подтверждена совместимость с другими животными;
- `-2` — опубликовано ограничение по другим животным;
- `+3` — спокойный портрет совпадает со спокойным характером питомца.

Карточки сортируются по score, затем по имени. Это делает порядок воспроизводимым и объяснимым.
Если пользователь явно выбрал собаку или кошку, животные другого вида исключаются из выдачи, а не просто получают меньший score. В одном проходе Tinder показываются максимум 6 непоказанных карточек.
Упоминание уже живущей у пользователя кошки или собаки не меняет желаемый вид питомца: он меняется только после явного намерения взять именно другой вид.

AI используется не для выдумывания рейтинга, а для:

- извлечения фактов из естественного ответа;
- определения, завершена ли текущая тема;
- формирования следующего вопроса;
- бережного текста ответа.

Если AI-режим выключен, работает локальный fallback с теми же ограничениями и тем же правилом запрета выдуманных фактов.

## Приватность

Полные ответы и внутренние факты владельца:

- не показываются в публичной анкете;
- не отправляются в frontend целиком;
- доступны менеджеру только через защищённую детализацию пользователя;
- используются только для дальнейшего подбора и продолжения интервью.
